# ניהול תגובות ולייקים — שרת, דשבורד ורכיבים להטמעה

אפליקציה אחת שמנהלת תגובות ולייקים לכל האתרים שלכם: שרת קטן ללא תלויות, דשבורד ניהול בעברית,
ושני רכיבים שמתווספים לכל דף בשורה אחת.

* **רישום מהיר** — מבקר נרשם בשלב אחד עם כתובת אימייל חוקית בלבד (בדיקת תחביר, חסימת כתובות זמניות
  ובדיקת DNS שהדומיין באמת מקבל דואר), או ממשיך כאנונימי אם האתר מרשה.
* **אישור לפני פרסום** — כל תגובה מגיעה לתור המתנה; אפשר לאשר, לדחות או למחוק לצמיתות.
* **דשבורד אחד לכל האתרים** — סקירה, סינון, חיפוש, פעולות קבוצתיות, ייצוא CSV וחסימת מבקרים.
* **הטמעה פשוטה** — תג `script` אחד ו־`div` לכל רכיב.

## שתי דרכים להריץ

| | איפה | מתי מתאים |
| --- | --- | --- |
| **Cloudflare Workers + D1** | בענן, בתוכנית החינמית | ברירת המחדל: אין שרת לתחזק, יש HTTPS וכתובת קבועה. הוראות מלאות ב־[`worker/README.md`](worker/README.md) |
| **שרת Node** | מקומי או VPS | פיתוח, או כשרוצים שהנתונים יישבו על מכונה משלכם |

שתי הגרסאות חולקות את אותה לוגיקה (`shared/`), את אותם קבצים סטטיים (`public/`) ואת אותה
בדיקת חוזה, כך שהמעבר ביניהן לא משנה כלום עבור האתרים שמוטמעים בהם הרכיבים.

```bash
# Cloudflare
cd app/worker && npm install && npx wrangler login
npx wrangler d1 create tells-engage      # להעתיק את ה־database_id ל־wrangler.toml
npm run db:init && npx wrangler secret put ADMIN_PASSWORD && npm run deploy
```

## התקנה והפעלה מקומית (Node)

דרישה יחידה: Node.js בגרסה 22.5 ומעלה (מודול `node:sqlite` המובנה). אין `npm install` — אין תלויות.

```bash
cd app
npm start
```

בהפעלה הראשונה תודפס סיסמת הדשבורד שנוצרה אוטומטית — שמרו אותה. אפשר גם לקבוע סיסמה מראש:

```bash
ADMIN_PASSWORD='הסיסמה-שלי' npm start
```

לאחר מכן:

| כתובת | מה יש שם |
| --- | --- |
| `http://localhost:4000/admin/` | דשבורד הניהול |
| `http://localhost:4000/` | דף הסבר קצר וקוד ההטמעה |
| `http://localhost:4000/demo.html?site=SITE_KEY` | דף הדגמה עם שני הרכיבים |
| `http://localhost:4000/healthz` | בדיקת חיים לניטור |

הגדרות נוספות: העתיקו את `.env.example` ל־`.env` ושנו מה שצריך.

### פקודות שירות

```bash
npm test                                  # חבילת הבדיקות (שרת אמיתי, בסיס נתונים זמני)
```

## הוספת הרכיבים לאתר

1. בדשבורד → **אתרים** → **אתר חדש**. נותנים שם, ואם רוצים — רשימת דומיינים מורשים.
2. לוחצים על **העתקת קוד ההטמעה**.
3. מדביקים בדף, במקום שבו הרכיבים אמורים להופיע:

```html
<script src="https://your-server/embed.js" data-site="st_xxxxxxxx" defer></script>

<div data-tells="likes"></div>
<div data-tells="comments"></div>
```

זה הכול. הרכיבים מביאים את העיצוב שלהם, מזהים את הדף לפי הנתיב שלו, ומתאימים את עצמם
למצב בהיר/כהה ולכיוון הכתיבה של הדף.

### אפשרויות לכל רכיב

| מאפיין | ברירת מחדל | תיאור |
| --- | --- | --- |
| `data-tells` | `comments` | סוג הרכיב: `comments` או `likes` |
| `data-site` | מהתג `script` | מפתח האתר, אם רוצים רכיבים משני אתרים באותו דף |
| `data-page` | הנתיב הנוכחי | מזהה הדף — שימושי ל־SPA או לרשימת פריטים בדף אחד |
| `data-title` | כותרת הדף | הכותרת שתוצג בדשבורד |
| `data-locale` | `he` | שפת הרכיב: `he` או `en` |
| `data-theme` | לפי המערכת | `light` או `dark` |

לרכיבים שנוצרים אחרי טעינת הדף (SPA):

```js
window.TellsEngage.mount();                       // מחפש רכיבים חדשים בדף
window.TellsEngage.mountElement(el, { widget: 'likes', page: '/item/42' });
```

### התאמת מראה

הרכיב חושף משתני CSS. אפשר לדרוס אותם מגיליון הסגנון של האתר:

```css
[data-tells] {
    --tlx-accent: #b45309;   /* צבע הפעולה */
    --tlx-radius: 8px;       /* עיגול פינות */
    --tlx-card: #fffaf0;     /* רקע הכרטיסים */
}
```

## איך זה עובד

### זהות המבקר

בפעם הראשונה שמבקר רוצה להגיב הוא בוחר:

* **אימייל** — הכתובת נבדקת בשלושה שלבים: תחביר מחמיר, רשימת ספקי אימייל זמניים,
  ובדיקת DNS שלדומיין יש שרת דואר. רק אז נוצרת הזהות. אין סיסמה ואין אימות במייל — זה רישום מהיר,
  לא חשבון משתמש.
* **אנונימי** — רק אם האתר מרשה זאת (מתג בדשבורד).

הזהות נשמרת בדפדפן כטוקן אקראי; בשרת נשמר רק ה־hash שלו. מבקר שחוזר עם אותה כתובת אימייל
מקבל את אותה זהות (וההיסטוריה שלו נשמרת) עם טוקן חדש.

לייקים לא עוצרים את המבקר בטופס: באתר שמרשה אנונימיים נוצרת זהות אנונימית ברקע.

### מסלול התגובה

1. הרכיב שולח את התגובה עם הטוקן של המבקר.
2. השרת בודק: אתר מוכר, דומיין מורשה, מבקר לא חסום, אורך התגובה, מלכודת בוטים,
   השהיה בין תגובות, מכסה שעתית וכפילות.
3. התגובה מקבלת ציון ספאם (קישורים, ביטויי ספאם, מילים חסומות שהגדרתם, צעקות).
4. באתר עם **אישור לפני פרסום** — התגובה ממתינה תמיד. באתר עם **פרסום מיידי** — היא מתפרסמת,
   אלא אם הציון גבוה ואז היא ממתינה.
5. הכותב רואה את התגובה שלו מסומנת "ממתינה לאישור"; שאר המבקרים לא רואים אותה עד האישור.

### מה נשמר

בסיס נתונים אחד (`data/engage.db`) עם: אתרים, מבקרים, תגובות, לייקים, יומן פעולות והגדרות.
כתובות IP נשמרות רק כ־hash עם מלח ייחודי להתקנה. כתובת האימייל של מגיב לעולם לא נחשפת ב־API
הציבורי — רק בדשבורד.

## אבטחה

* **CORS לפי אתר** — לכל אתר רשימת דומיינים מורשים. בקשה מדומיין אחר נדחית (רשימה ריקה = כל דומיין,
  נוח בזמן הקמה, כדאי לצמצם אחר כך).
* **מפתח אתר ניתן להחלפה** — אם המפתח דלף, "החלפת מפתח" מנתקת מיידית כל רכיב שמשתמש בישן.
* **דשבורד** — סיסמה עם scrypt (Node) או PBKDF2 (Cloudflare), עוגיית `HttpOnly` + `SameSite=Strict`, וכותרת `X-Tells-Admin`
  שחוסמת שליחת טפסים מאתר זר. הגבלת קצב על ניסיונות התחברות.
* **תוכן מבקרים** — נשמר כטקסט ומוצג כטקסט בלבד, גם ברכיב וגם בדשבורד. רק כתובות URL הופכות
  לקישורים, עם `rel="nofollow ugc noopener"`.
* **הגבלות קצב** — לפי כתובת IP לכל סוג פעולה, ובנוסף השהיה ומכסה שעתית לכל מבקר.

בפרודקשן על Node: הפעילו `SECURE_COOKIES=true` מאחורי HTTPS, ו־`TRUST_PROXY=true` רק אם יש proxy
שלכם שמגדיר `X-Forwarded-For`. ב־Cloudflare שני אלה מטופלים ממילא.

## ממשק ה־API

### ציבורי (הרכיבים) — `/api/v1`

| שיטה | נתיב | תיאור |
| --- | --- | --- |
| `GET` | `/site?site=KEY` | הגדרות ציבוריות של האתר |
| `POST` | `/visitors` | רישום מהיר: `{ site, mode: "email"\|"anonymous", email, name }` |
| `GET` | `/comments?site=KEY&page=/path` | תגובות מאושרות (+ הממתינות של הקורא עצמו) |
| `POST` | `/comments` | תגובה חדשה: `{ site, page, body, parentId? }` |
| `GET` | `/likes?site=KEY&page=/path` | מונה לייקים ומצב הקורא |
| `POST` | `/likes` | הוספה או ביטול של לייק |

הטוקן נשלח בכותרת `Authorization: Bearer <token>`.

### ניהול — `/admin/api`

התחברות ב־`POST /login`, וכל בקשה נושאת את הכותרת `X-Tells-Admin: 1`.

`/overview` · `/sites` · `/sites/:id` · `/sites/:id/rotate-key` · `/comments` · `/comments/:id/status` ·
`/comments/:id` · `/comments/bulk` · `/comments/export` · `/likes` · `/visitors` · `/visitors/:id/block` ·
`/settings` · `/audit` · `/password`

## הרצה בפרודקשן

השרת הוא תהליך Node יחיד שמאזין על פורט. מומלץ להעמיד מולו reverse proxy עם HTTPS ולהריץ
את התהליך תחת systemd:

```ini
[Unit]
Description=Tells Engage
After=network.target

[Service]
WorkingDirectory=/srv/engage/app
ExecStart=/usr/bin/node --disable-warning=ExperimentalWarning server/index.js
Environment=PORT=4000
Environment=SECURE_COOKIES=true
Environment=TRUST_PROXY=true
Environment=ADMIN_PASSWORD=...
Restart=always
User=engage

[Install]
WantedBy=multi-user.target
```

גיבוי = העתקה של `data/engage.db` (עדיף עם `sqlite3 .backup` בזמן שהשרת רץ).
