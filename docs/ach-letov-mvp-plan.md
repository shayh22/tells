# אח לטוב — תוכנית מימוש MVP

מסלול פיתוח מרוכז של עשרה ימי עבודה ב‑Lovable מעל Supabase: הרשמה דו‑מסלולית
(מבקש עזרה / אח מלווה), ספריית סרטונים עם העלאה ושיוך, ומעקב אחרי מה שכל משתמש
באמת עשה. חדרי דיון ושיעורי תורה נדחים לשלב ב׳ — אבל הסכימה מוכנה לקלוט אותם.

| היקף | סטאק | מסכים | טבלאות |
| --- | --- | --- | --- |
| 10 ימי עבודה | Lovable + Supabase | 14 | 11 |

---

## 1. גבולות הגרסה

**נכנס ל‑MVP**

- **הרשמה דו‑מסלולית** — מסלול נפרד למבקש עזרה ולאח מלווה, עם אונבורדינג ייעודי ואישור מנהל.
- **בקשות עזרה ושיבוץ** — מבקש פותח בקשה, מנהל משבץ, שני הצדדים מאשרים.
- **ספריית סרטונים** — העלאה ישירה, קטגוריות, נראות מדורגת, שיוך אישי.
- **מעקב משתמשים** — מי צפה וכמה, יומן קשר, ודשבורד שמצביע על מי שנשמט.

**לא נכנס — במכוון**

- חדרי דיון — מחייבים ניהול קהילה ומודרציה. חוב תפעולי, לא טכני.
- שיעורי תורה — לוח זמנים, מגישים, שידור והרשמות. מערכת בפני עצמה.
- צ׳אט בזמן אמת — הקשר מתנהל בטלפון, והמערכת מתעדת אותו ביומן.
- אפליקציה נייטיב — אתר רספונסיבי כ‑PWA מספיק בשלב הזה.

## 2. ארכיטקטורה והחלטות

| שכבה | בחירה | למה |
| --- | --- | --- |
| ממשק | React + Vite + TS | ברירת המחדל של Lovable |
| עיצוב | Tailwind + shadcn/ui | טוקנים ב‑index.css, RTL, רכיבים נגישים |
| הזדהות | Supabase Auth | אימייל+סיסמה ו‑Google; OTP בשלב ב׳ |
| נתונים | Postgres + RLS | הרשאות בבסיס הנתונים, לא בלקוח |
| קבצים | Supabase Storage | העלאה ישירה, קישורים חתומים |
| לוגיקת שרת | Edge Functions | שלוש בלבד: קישור חתום, מיילים, דוח שבועי |
| מיילים | Resend | אישור, שיבוץ, תזכורת |
| ניטור | Sentry | חמש דקות התקנה |

**שבע החלטות שחוסכות ימים**

1. **עברית ו‑RTL מהרגע הראשון** — `<html dir="rtl" lang="he">`, ורק מחלקות לוגיות
   (`ms-*`, `me-*`, `ps-*`, `text-start`). אף פעם לא `ml-*` או `text-left`.
2. **קובץ ידע בפרויקט Lovable** עם הכללים הקבועים — נכנס לכל בקשה ומונע סחיפה.
3. **סכימה לפני מסכים** — יום שלם על טבלאות ו‑RLS.
4. **מצב צ׳אט לתכנון, מצב בנייה לביצוע.**
5. **עריכה נקודתית** לשינויי טקסט וריווח במקום פרומפט מלא.
6. **GitHub מחובר ביום הראשון** — ענף לכל ספרינט.
7. **שתי סביבות Supabase** — לעולם לא לבדוק על נתוני אמת.

## 3. תפקידים ומסעות

| תפקיד | מה הוא עושה | מה הוא רואה |
| --- | --- | --- |
| מבקש עזרה | נרשם, פותח בקשה, צופה בסרטונים ששויכו לו | הבקשות, האח שלו, הסרטונים, ההתקדמות |
| אח מלווה | נרשם, ממתין לאישור, מקבל שיבוץ, מתעד מפגשים | המלווים שלו, יומן קשר, ספריית סרטונים |
| מנהל | מאשר, משבץ, מעלה תוכן, עוקב | הכול, כולל דשבורד ויומן פעולות |

**המסע המרכזי**

1. בחירת מסלול במסך אחד: *אני מחפש עזרה* / *אני רוצה לעזור*.
2. מבקש עזרה — שלושה שדות בלבד (שם, טלפון, עיר). חסם נמוך זה קריטי.
3. אח מלווה — פרופיל מורחב, ואז מסך "ממתין לאישור" + מייל למנהל.
4. אישור מנהל → `status = active` → מייל ברוך הבא.
5. המבקש פותח בקשה: תחום, תיאור, דחיפות, העדפת מגדר.
6. המנהל רואה מועמדים מדורגים ומשבץ בלחיצה.
7. אישור דו‑צדדי → הקשר פעיל → **ורק אז** נחשפים פרטי הקשר.
8. מכאן: יומן קשר, סרטונים משויכים, והתקדמות נמדדת.

> **החלטת מוצר:** פרטי קשר אישיים נחשפים רק אחרי אישור דו‑צדדי. זה עולה מסך אחד
> נוסף וחוסך את הבעיה הכי מסוכנת שיכולה להיות למערכת כזאת.

## 4. מודל הנתונים

| טבלה | תפקיד | שדות מרכזיים |
| --- | --- | --- |
| `profiles` | כל משתמש, בכל תפקיד | role, status, city, gender |
| `helper_profiles` | נתוני האח המלווה | areas[], languages[], max_active |
| `seeker_profiles` | נתוני מבקש העזרה | needs[], preferred_gender |
| `help_requests` | בקשת עזרה פתוחה | category, urgency, status |
| `matches` | הקשר בין השניים | helper_id, seeker_id, status |
| `check_ins` | יומן קשר — כל מפגש | kind, minutes, mood, summary |
| `videos` | ספריית הסרטונים | storage_path, visibility, published |
| `video_assignments` | שיוך סרטון לאדם | video_id, assigned_to, due_at |
| `video_progress` | מעקב צפייה | percent, completed_at |
| `notifications` | התראות בתוך המוצר | kind, payload, read_at |
| `audit_log` | מי עשה מה ומתי | actor_id, action, target |

```sql
create type app_role       as enum ('seeker','helper','admin');
create type account_status as enum ('pending','active','suspended');
create type match_status   as enum ('proposed','accepted','active','ended','declined');
create type video_visibility as enum ('public','helpers','assigned');

create table profiles (
  id         uuid primary key references auth.users on delete cascade,
  full_name  text not null,
  phone      text,
  city       text,
  gender     text check (gender in ('male','female')),
  birth_year int,
  avatar_url text,
  role       app_role       not null default 'seeker',
  status     account_status not null default 'pending',
  created_at timestamptz    not null default now()
);

create table matches (
  id         uuid primary key default gen_random_uuid(),
  request_id uuid references help_requests on delete set null,
  helper_id  uuid not null references profiles,
  seeker_id  uuid not null references profiles,
  status     match_status not null default 'proposed',
  started_at timestamptz,
  ended_at   timestamptz,
  created_at timestamptz not null default now()
);

-- מונע שיבוץ כפול של אותו זוג
create unique index one_live_match on matches (helper_id, seeker_id)
  where status in ('proposed','accepted','active');

create table videos (
  id            uuid primary key default gen_random_uuid(),
  uploader_id   uuid not null references profiles,
  title         text not null,
  description   text,
  category      text not null,          -- מרחיב בהמשך ל'שיעור'
  storage_path  text not null,
  thumbnail_url text,
  duration_sec  int,
  visibility    video_visibility not null default 'assigned',
  published     boolean not null default false,
  created_at    timestamptz not null default now()
);

create table video_progress (
  video_id        uuid references videos on delete cascade,
  user_id         uuid references profiles on delete cascade,
  seconds_watched int not null default 0,
  percent         int not null default 0,
  completed_at    timestamptz,
  last_seen_at    timestamptz not null default now(),
  primary key (video_id, user_id)
);
```

## 5. הרשאות ואבטחה

המערכת מחזיקה מידע על אנשים במצוקה. RLS מופעל על כל טבלה ביום הראשון — לא אחרי
שהמסכים עובדים. Lovable יציע לפעמים לכבות RLS כדי "שהשאילתה תעבוד"; זו תמיד
תשובה שגויה.

```sql
create or replace function public.is_admin()
returns boolean language sql security definer stable
set search_path = public as $$
  select exists (select 1 from profiles
                 where id = auth.uid() and role = 'admin');
$$;

alter table profiles enable row level security;

create policy "own profile" on profiles
  for all using (auth.uid() = id) with check (auth.uid() = id);

create policy "matched party profile" on profiles
  for select using (exists (
    select 1 from matches m
    where m.status in ('accepted','active')
      and ((m.helper_id = auth.uid() and m.seeker_id = profiles.id)
        or (m.seeker_id = auth.uid() and m.helper_id = profiles.id))));

create policy "admin all" on profiles
  for all using (public.is_admin()) with check (public.is_admin());

alter table check_ins enable row level security;
create policy "parties to the match" on check_ins
  for all using (exists (
    select 1 from matches m where m.id = check_ins.match_id
      and auth.uid() in (m.helper_id, m.seeker_id)) or public.is_admin());
```

- **תפקיד לא נקבע מהלקוח** — הרשמה תמיד יוצרת `seeker` / `pending`.
- **מחיקה רכה** ליומן קשר ולבקשות. אף פעם לא `delete` על היסטוריה אנושית.
- **יומן פעולות** על כל פעולת מנהל.
- **הסכמה מפורשת** לתקנון ולפרטיות, עם חותמת זמן.

## 6. וידאו: העלאה וצפייה

בלי טרנסקודינג, בלי ספק חיצוני, בלי HLS.

| מאגר | גישה | מגבלות | מי מעלה |
| --- | --- | --- | --- |
| `videos` | פרטי · קישור חתום ל‑2 שעות | עד 300MB · mp4, webm, mov | מנהל, מלווה |
| `thumbnails` | ציבורי | עד 2MB · jpg, webp | נוצר בהעלאה |
| `avatars` | ציבורי | עד 2MB · jpg, webp | המשתמש |

**זרימת העלאה**

1. בדיקת סוג וגודל בצד הלקוח לפני שנוגעים ברשת.
2. תמונה ממוזערת נלכדת מהפריים בשנייה השנייה דרך `canvas`; האורך נקרא מ‑`video.duration`.
3. העלאה ישירה לנתיב `{uploader_id}/{uuid}.mp4` עם סרגל התקדמות אמיתי.
4. שורה ב‑`videos` נכתבת רק אחרי שההעלאה הסתיימה — אין רשומות יתומות.
5. הסרטון עולה כטיוטה; מנהל מפרסם.

**שלוש רמות נראות** — `assigned` (ברירת מחדל, אישי) · `helpers` (הדרכה למלווים) ·
`public` (כל משתמש רשום; לא אורחים).

קישור קבוע למאגר ציבורי מודלף לוואטסאפ ונשאר חי לנצח. קישור חתום ל‑2 שעות נוצר
בכל צפייה, מכבד את ה‑RLS, ומת מעצמו.

## 7. מעקב משתמשים

**שכבה א׳ — צפייה בסרטון.** הנגן שולח עדכון כל 15 שניות ובאירועי `pause`/`ended`:

```ts
await supabase.from('video_progress').upsert({
  video_id: id,
  user_id: user.id,
  seconds_watched: Math.floor(el.currentTime),
  percent: Math.round((el.currentTime / el.duration) * 100),
  completed_at: pct >= 90 ? new Date().toISOString() : null,
  last_seen_at: new Date().toISOString(),
}, { onConflict: 'video_id,user_id' });
```

סרטון נחשב "הושלם" ב‑90% — כמעט אף אחד לא יושב עד סוף הקרדיטים.

**שכבה ב׳ — יומן קשר.** ארבעה שדות בלבד: סוג (שיחה/מפגש/הודעה), משך בדקות,
תחושה 1–5, וסיכום חופשי. כל שדה נוסף מוריד את שיעור המילוי.

**שכבה ג׳ — דשבורד המנהל**

| אינדיקטור | הגדרה | למה זה חשוב |
| --- | --- | --- |
| בקשות ללא שיבוץ | `new` מעל 72 שעות | מישהו ביקש עזרה ולא קיבל תשובה |
| קשרים שקטים | אין תיעוד 14 יום | הסימן המוקדם ביותר לנשירה |
| מלווים ממתינים | `pending` | מתנדב שממתין שבוע — מתנדב שאבד |
| סרטונים לא נצפו | שויכו לפני 7 ימים, מתחת ל‑10% | תוכן לא רלוונטי או משתמש שנעלם |
| עומס לפי מלווה | פעילים מול `max_active` | מונע שחיקת מתנדבים |

כל אלה נכתבים כ‑Postgres Views; הדשבורד קורא View אחד לכל כרטיס.

## 9. תוכנית הספרינטים

כל ספרינט מסתיים במשהו שאפשר להדגים למישהו אמיתי — לא בחצי יכולת.

- פרויקט Lovable, חיבור Supabase ו‑GitHub, קובץ ידע.

**מדגימים:** נרשמים, מתחברים, ורואים מסך בית ריק בעברית.

**מדגימים:** בקשה נפתחת, משובצת, מאושרת — ושני הצדדים רואים זה את זה.

### S3 · וידאו — ימים 6–7
- העלאה עם התקדמות ותמונה ממוזערת · ספרייה עם סינון וחיפוש · נגן עם קישור חתום

**מדגימים:** מלווה מעלה סרטון, משייך, המבקש צופה — וזה נרשם.

### S4 · מעקב ודשבורד — ימים 8–9
- יומן קשר וציר זמן · Views לחמשת האינדיקטורים · דשבורד מנהל · סרגל התקדמות
  אישי · שלושה מיילים אוטומטיים ודוח שבועי.

**מדגימים:** מנהל פותח דשבורד ורואה מיד מי נשמט.

### S5 · ליטוש ועלייה לאוויר — יום 10

## 10. פרומפטים ל‑Lovable

### קובץ הידע (נכנס פעם אחת, משפיע על הכול)

```text
זהו "אח לטוב" — מערכת שמחברת בין אנשים שמבקשים עזרה לבין מתנדבים שמלווים אותם.

כללים קבועים לכל שינוי בפרויקט:
• השפה עברית בלבד, הכיוון RTL. ב-html יש dir="rtl" ו-lang="he".
• ב-Tailwind להשתמש רק במחלקות לוגיות: ms-, me-, ps-, pe-, start-, end-,
  text-start, text-end. אין להשתמש ב-ml-, mr-, pl-, pr-, text-left, text-right.
• כל הצבעים והגופנים מגיעים מטוקנים ב-index.css ומ-tailwind.config.
  אין צבעים קשיחים בקומפוננטות.
• רכיבי shadcn/ui בלבד. אין להתקין ספריות ממשק נוספות.
• RLS מופעל על כל טבלה. לעולם לא לכבות RLS כדי לפתור שאילתה — לתקן את המדיניות.
• תפקיד המשתמש לעולם לא נקבע מהלקוח. הרשמה יוצרת תמיד seeker/pending.
• אין לשנות סכימת בסיס נתונים בלי לשאול אותי קודם.
• כל טופס: ולידציה עם zod, מצב טעינה, הודעת שגיאה בעברית ידידותית.
• מובייל תחילה. רוב המשתמשים מגיעים מהטלפון.
• שמות תפקידים בממשק: "מבקש עזרה", "אח מלווה", "מנהל".
```

### ספרינט 0 — מעטפת ועיצוב

```text
בנה את שלד האפליקציה בלבד, בלי לוגיקה עסקית.

1. הגדר מערכת עיצוב ב-index.css: צבע ראשי ירוק-אורן עמוק (#1A544A), צבע משני
   פליז חמים (#946C22), רקע ניטרלי בהיר עם נטייה ירקרקה, מצב כהה מלא.
   גופן Assistant לגוף הטקסט ו-Frank Ruhl Libre לכותרות, מ-Google Fonts.
2. שלד תצוגה: כותרת עליונה עם לוגו טקסטואלי, תפריט מובייל, תפריט צד בצד ימין.
3. הזדהות מלאה מול Supabase: הרשמה, כניסה, שחזור סיסמה, יציאה.
   עטוף בקונטקסט AuthProvider עם hook בשם useAuth.
4. נתיבים מוגנים: לא מחובר ← auth; helper עם status='pending' ← pending.
5. רכיבי מצב אחידים: טעינה (skeleton), ריק, ושגיאה.

אל תיצור עדיין טבלאות — הסכימה כבר קיימת בבסיס הנתונים.
```

### ספרינט 1 — הרשמה דו‑מסלולית

```text
בנה את זרימת ההרשמה והאונבורדינג.

1. עמוד נחיתה: הסבר קצר ושני כפתורים גדולים — "אני מחפש עזרה" ו"אני רוצה לעזור".
   הבחירה נשמרת ומועברת לתהליך ההרשמה.
2. אחרי הרשמה מוצלחת, נתב ל-onboarding עם המסלול שנבחר.
3. מסלול מבקש עזרה — שלושה שדות בלבד: שם מלא, טלפון, עיר. בסיום נכתב
   seeker_profiles ו-status עובר ל-active. חשוב שיהיה קצר ככל האפשר.
4. מסלול אח מלווה — טופס בשלושה צעדים: פרטים אישיים, תחומי ליווי (בחירה מרובה),
   זמינות ומספר מלווים מקסימלי. בסיום נכתב helper_profiles, התפקיד מבוקש כ-helper
   וה-status נשאר pending.
5. עמוד pending: הודעה מכובדת שהבקשה בבדיקה, עם אפשרות לערוך את הפרופיל.
6. בפאנל הניהול, מסך "מלווים ממתינים" עם כרטיס לכל מועמד וכפתורי אישור ודחייה.
   אישור מעדכן role ו-status, וכותב שורה ב-audit_log.

השתמש ב-react-hook-form עם zod. כל הודעות השגיאה בעברית.
```

### ספרינט 2 — בקשות ושיבוץ

```text
בנה את מנגנון הבקשות והשיבוץ.

1. טופס בקשת עזרה: תחום, תיאור חופשי, דחיפות (רגילה/גבוהה/דחופה), העדפת מגדר
   מלווה. נשמר ב-help_requests עם status='new'.
2. עמוד בקשה עם ציר זמן סטטוס: נפתחה ← בטיפול ← שובצה ← פעילה.
3. בפאנל הניהול, תור הבקשות ממוין לפי דחיפות וגיל. לכל בקשה, רשימת מלווים
   מדורגת: התאמת תחום, אותה עיר, התאמת מגדר, ופחות קשרים פעילים מהמקסימום שלו.
   הצג את הניקוד ואת הסיבה.
4. שיבוץ יוצר שורה ב-matches עם status='proposed' ושולח התראה לשני הצדדים.
5. שני הצדדים רואים כרטיס "שיבוץ ממתין" עם אישור או דחייה. אחרי ששניהם אישרו —
   status עובר ל-active, started_at מתמלא, ורק אז מוצגים שם מלא וטלפון של הצד
   השני. לפני כן מוצג שם פרטי בלבד.
6. עמוד "הקשרים שלי" עם כרטיס לכל קשר.

חשוב: פרטי קשר לא נחשפים לפני אישור דו-צדדי.
```

### ספרינט 3 — וידאו

```text
בנה את מערכת הסרטונים מול Supabase Storage.

1. מסך העלאה: גרירה או בחירת קובץ, בדיקת סוג (mp4/webm/mov) וגודל (עד 300MB)
   לפני העלאה, סרגל התקדמות אמיתי, ואפשרות ביטול.
2. לפני ההעלאה, טען את הקובץ לאלמנט video מוסתר, קרא את duration, ולכוד פריים
   בשנייה השנייה ל-canvas כתמונה ממוזערת. העלה את שניהם.
3. הנתיב במאגר videos הוא {user_id}/{uuid}.{ext}. שורה ב-videos נכתבת רק אחרי
   שההעלאה הצליחה, עם published=false.
4. ספריית סרטונים: רשת כרטיסים עם תמונה ממוזערת, אורך, קטגוריה, וסרגל התקדמות
   צפייה אם התחיל. סינון לפי קטגוריה וחיפוש חופשי.
5. עמוד נגן: צור קישור חתום לשעתיים דרך createSignedUrl. שמור התקדמות
   ב-video_progress כל 15 שניות ובאירועי pause ו-ended, ב-upsert על המפתח
   video_id+user_id. מעל 90 אחוז — סמן completed_at. בכניסה חוזרת, הצע להמשיך
   מהנקודה שנשמרה.
6. בעמוד הקשר, כפתור "שייך סרטון" שפותח בורר מהספרייה וכותב ל-video_assignments
   עם תאריך יעד אופציונלי.
7. בפאנל הניהול, מסך אישור סרטונים ממתינים.
```

### ספרינט 4 — מעקב ודשבורד

```text
בנה את שכבת המעקב.

1. בעמוד הקשר, טופס תיעוד קצר: סוג (שיחה/מפגש/הודעה), משך בדקות, תחושה 1 עד 5,
   וסיכום חופשי. נשמר ב-check_ins. מתחתיו ציר זמן של כל התיעודים.
2. כרטיס התקדמות בעמוד הקשר: ימים מהשיבוץ, מספר מפגשים, סך דקות, אחוז השלמת
   סרטונים, ומגמת התחושה כגרף קו קטן.
3. דשבורד מנהל עם חמישה כרטיסים, כל אחד קורא מ-view ייעודי: בקשות ללא שיבוץ מעל
   72 שעות, קשרים ללא תיעוד 14 יום, מלווים ממתינים לאישור, סרטונים ששויכו לפני
   שבוע ולא נצפו, ועומס לפי מלווה. כל כרטיס מציג מספר גדול ורשימה לחיצה.
4. מסך "כל המשתמשים" למנהל, עם חיפוש, סינון לפי תפקיד וסטטוס, וכניסה לפרופיל.

צור את ה-views ב-SQL תחילה והצג לי אותם לאישור לפני שאתה בונה את הממשק.
```

### ספרינט 5 — ליטוש

```text
עבור על כל האפליקציה וטפל בליטוש הסופי.

1. נגישות: כל שדה עם תווית, כל אייקון-כפתור עם aria-label, מצב פוקוס נראה,
   ניווט מלא במקלדת, ניגודיות תקינה בשני המצבים. בדוק גם עם קורא מסך.
2. מובייל: עבור על כל מסך ברוחב 375 פיקסלים. אזורי מגע לפחות 44 פיקסלים.
   טבלאות הופכות לכרטיסים.
3. אין מסך ריק ללא הסבר — לכל מצב ריק כותרת, משפט הסבר, ופעולה מוצעת.
4. הוסף PWA: מניפסט, אייקונים, ותמיכה בהתקנה למסך הבית.
5. עבור על כל טופס: מניעת שליחה כפולה, הודעת הצלחה, טיפול בשגיאת רשת.
6. הוסף עמוד 404 ועמוד שגיאה כללי בעברית.
```

## 11. הגדרת סיום ו‑QA

| היקף | תנאי סיום |
| --- | --- |
| לכל מסך | עברית ו‑RTL · תקין ב‑375px · טעינה/ריק/שגיאה · ניווט מקלדת · שני מצבי תצוגה |
| לכל טופס | ולידציה · שגיאות בעברית · נעילת כפתור בשליחה · הודעת הצלחה · הנתונים נשמרו |
| לכל טבלה | RLS פעיל · נבדק שמשתמש א׳ לא מגיע לנתוני ב׳ · אינדקסים על מפתחות זרים |
| לפני עלייה | גיבוי · Sentry · אין מפתחות בקוד · תקנון ופרטיות · חשבון מנהל אמיתי |

**שלושה תרחישי בדיקה מקצה לקצה**

1. **המסלול המלא:** מלווה נרשם ← מאושר ← מבקש נרשם ← פותח בקשה ← מנהל משבץ ←
   שניהם מאשרים ← תיעוד מפגש ← שיוך סרטון ← צפייה ← הופעה בדשבורד.
2. **ניסיון חדירה:** כמבקש א׳, נסה לגשת לנתוני מבקש ב׳ — שינוי מזהה בכתובת,
   קריאת API ישירה, קישור לסרטון לא משויך. כולם צריכים להיכשל.
3. **קצוות:** קובץ 400MB, סוג לא נתמך, ניתוק רשת באמצע העלאה, שני מנהלים
   שמשבצים את אותה בקשה בו זמנית.

## 12. סיכונים ושלב ב׳

| סיכון | חומרה | מענה |
| --- | --- | --- |
| דליפת מידע רגיש בין משתמשים | קריטי | RLS מיום ראשון + תרחיש חדירה בכל ספרינט |
| שיבוץ לא מתאים בין אנשים | קריטי | מנהל אנושי מאשר כל שיבוץ; הדירוג ממליץ בלבד |
| עלות אחסון וידאו גדלה | בינוני | מגבלת 300MB, מכסה חודשית, ניטור נפח |
| שבירת RTL בעדכוני ממשק | בינוני | כלל בקובץ הידע + בדיקה בכל ספרינט |
| מתנדבים נושרים בשקט | בינוני | אינדיקטור "קשרים שקטים" + דוח שבועי |
| Lovable משנה סכימה מיוזמתו | נמוך | איסור מפורש בקובץ הידע; ענף לכל ספרינט |

**איך מכינים את הקרקע לחדרי דיון ולשיעורי תורה** — בעלות אפסית, כבר עכשיו:

- `videos.category` כטקסט חופשי ולא רשימה סגורה. שיעור תורה הוא קטגוריה נוספת.
- `group_id` ניתן לריק ב‑`matches`. חדר דיון הוא קבוצה שבה כמה קשרים חולקים מרחב.
- `notifications` גנרית עם `kind` ו‑`payload` חופשי — כל התראה עתידית נכנסת לשם.

**מדדי הצלחה לחודש הראשון**

- זמן עד שיבוץ: חציון מתחת ל‑48 שעות.
- קשרים חיים: מעל 70% עם תיעוד ב‑14 הימים האחרונים.
- השלמת סרטונים: מעל 50% מהמשויכים נצפים עד 90%.
- קליטת מתנדבים: מעל 80% מהנרשמים כמלווים מגיעים לשיבוץ ראשון.
